# Developer Workflow Router

Select one workflow that best matches the request:

- Project changes: cleanup, format, implement, readability, refactor, scaffold
- Testing and review: predict issues, review, security scan, test
- Maintenance: create or find TODOs, fix imports or TODOs, remove obvious comments
- Project knowledge: contribution readiness, docs, senior explanation, project understanding
- Delivery and continuity: commit, session start or end, TODOs to issues, undo

## Execute safely

1. Inspect repository status, project instructions, relevant code, and existing checks.
2. Confirm ambiguous scope before making material changes.
3. Preserve unrelated user work and follow existing project conventions.
4. Use available Codex capabilities; do not imply unavailable persistence, memory, hooks, or delegation.
5. Do not create automatic checkpoints, stage all files, commit, push, create issues, modify remotes, or alter memory unless explicitly requested.
6. Resolve exact targets before cleanup or rollback and prefer recoverable, narrow actions.
7. Treat review, explanation, and diagnosis as read-only unless fixes are also requested.
8. Verify with the project-specific formatting, lint, type, test, build, browser, and security checks appropriate to the authorized work.

Report the selected workflow, material changes, validation evidence, and remaining risks.
